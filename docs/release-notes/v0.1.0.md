Status: release candidate

Name: Documentation + Static Validation Release

## What Works

- 五朵云均保留独立目录、设计文档、module/live/examples/tests 组织方式。
- AWS 有完整的 14 层 live stack 入口和企业级深化路线图。

- AWS evidence contract 已覆盖 apply report、rollback report、sanitized plan output 和 evidence directory 约定；不包含真实云输出。

## Static Validation

本地已验证：

```bash
python3 tools/static_release_gate.py
terraform fmt -check -recursive
conftest verify --policy multi-cloud/aws/policies
conftest verify --policy multi-cloud/alicloud/policies
checkov -d multi-cloud --config-file .checkov.yaml --framework terraform --quiet --compact
tflint --recursive --format compact
TF_PLUGIN_CACHE_DIR=/private/tmp/openlzkit-terraform-cache \
  terraform init -backend=false && terraform validate # repeated for every multi-cloud/aws Terraform directory
```

已验证的 Rego 单元测试：

- AWS policies: 17 passed.
- Alibaba Cloud policies: 10 passed.

已验证的扫描门禁：

- Checkov: 271 passed, 0 failed, 0 parsing errors.
- TFLint: recursive lint passed.
- AWS Terraform static validation: every AWS example, live stack and module passed `init -backend=false` + `validate`.
- Azure `40-security`、`45-compliance` 与 `modules/compliance` Terraform validate passed.

## Static-only

- Terraform `validate` 需要 provider init；本地无网络时会被 registry 访问限制阻塞。
- TFLint 和 Checkov 依赖本地工具或 CI 环境；Codex 沙箱内运行 TFLint 可能需要在沙箱外执行，以允许 Go plugin IPC。
- Azure、GCP、腾讯云当前以 static blueprint 和文档/目录完整性为主，尚未声明真实 sandbox apply。

## Known Limitations

- `v0.1.0` 不声称任何云已完成真实 sandbox verified path。
- AWS verified path 的真实 apply 结果应写入 [../demo/aws-sandbox-apply-report.md](../demo/aws-sandbox-apply-report.md)，且只提交脱敏摘要。
- AWS rollback 演练结果应写入 [../demo/aws-sandbox-rollback-report.md](../demo/aws-sandbox-rollback-report.md)，并与 apply evidence 日期对齐。
- 合规映射是工程控制矩阵，不是 CIS、ISO、SOC2 或等保认证结论。
- 生产落地仍应优先评估 AWS Control Tower / AFT、企业审批流程、身份源和审计归档要求。
